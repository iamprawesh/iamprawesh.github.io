// currently building

On-device image quality for AI

At Evolve I'm building the camera layer for one of our AI-powered features in native Android. The AI model is only as good as the photos it gets, so the app checks every frame for blur and sharpness on the phone before anything is uploaded.

  • A CameraX pipeline that runs analysis on live frames as the user shoots.
  • A sharpness and blur check on each frame, so only clear images get through.
  • Feedback on screen that tells the user to hold steady or retake the photo.
  • The best frames go to the AI model, which means fewer bad results and less wasted upload and compute.

Apps I've built

K

KhelSlot: futsal booking platform

Personal product · Flutter (Web, Android, iOS) · Firebase

A booking platform for futsal venues in Nepal, built as one Flutter codebase for three kinds of users. Players open a venue link, see which slots are free, and book over WhatsApp without signing up. Venue admins manage the availability grid, walk-in bookings, pricing, peak hours and reports. The software owner runs every venue, admin login and membership from a single panel.

Architecture

Pages / Widgets UI only
Cubits view models · flutter_bloc
Repository interfaces Auth · Venue · Booking
Firebase impl
In-memory impl

The layers are feature-first and use MVVM, with Cubits acting as the view models. Pages never call Firebase directly. Business rules such as pricing, slots, courts, memberships and stats are pure Dart functions, so they're easy to unit-test.

What's in it

  • Firestore real-time streams go to the Cubits, then to the UI
  • Security rules are role-based and scoped to each venue
  • Peak pricing by hour, weekday or special date
  • Split courts: a 7-a-side ground can be booked as two 5-a-side halves
  • Repeat bookings, booking codes and a loyalty free game
  • Memberships and trials, plus revenue reports (daily, weekly, monthly)
  • Responsive: sidebar at 900px and wider, bottom navigation on phones
  • 31 unit, cubit and widget tests; runs on Firebase or an offline in-memory backend
